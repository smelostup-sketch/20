# CHANGELOG — Q7.12_RengarPreOmega
Проблема: боковое скольжение/дрожь при старте и остановке движения игрока.
База: Q7.11.RengarPreOmega. Диагностика: `q_tools/diag_sliding_report.md` (Q7.11),
инструменты `q_tools/diag_anim.gd`, `q_tools/diag_move.gd` (DIAG_SCENARIO=STRAIGHT|IDLE|MOUSE_OFFSET).

## Вердикт диагностики
Гипотеза «анимация» НЕ подтверждена (замер): root motion в клипах отсутствует,
латераль Hips Idle ±0.6 см / Run ±1.2 см (естественный цикл), позовый щелчок
Idle↔Run ≤ 9 мм, пол/`is_on_floor` стабильны, флип-флопа анимаций нет.
Причина — слой движения: (A) направление из отстающего базиса тела, (B) поосевое
торможение `move_toward`, кривящее вектор скорости.

## Изменения (только A+B; C — дрожь/рендер — отложено до feel-чека заказчиком)
1. `Scripts/StateComponent.gd`
   - Экспорт `movement_yaw_provider_path` + `_movement_basis()`: направление
     движения (ходьба, dodge, dash) — из намерения взгляда `get_view_yaw()`,
     а не из базиса тела, который догоняет камеру с лагом (lerp 12/s в
     `ThirdPersonCamera._process`). Без провайдера — fallback на базис
     владельца (враг/манекен без камеры; ядро owner-agnostic).
   - `apply_physics()`: единая векторная ветка `Vector2.move_toward(v, target, rate*delta)`
     вместо поосевых `move_toward` по X и Z. Поосевое гашение поворачивало
     вектор скорости к доминирующей оси (замер Q7.11 MOUSE_OFFSET: угол
     (скорость, фейсинг) на стопе 0.6°→13.7°→35° — боковое «конькобежное»
     скольжение). Числа не менялись: acceleration/deceleration/action_exit_deceleration — прежние экспорты.
2. `Основная_сцена.tscn`
   - StateComponent игрока: `movement_yaw_provider_path = NodePath("../../Camera3D")`.
   - StateComponent врага и манекена НЕ тронуты (fallback на базис).
   - `EnemyController` не использует `apply_physics` (пишет velocity сам) — ИИ не затронут.

## Известный остаток (осознанно отложен, задача C)
- Корпус визуально догоняет камеру с лагом → при резком флике мыши (+35°) на
  ~0.2–0.4 с угол (скорость, фейсинг) до 15.4° (замер T=148); при типичных
  мелких движениях мыши (5–10°) — единицы градусов. Траекторию это больше не
  искажает (скорость всегда по камере), только позу корпуса.
- Лечение (следующий заход после feel-чека): поворот корпуса в `_physics_process`
  кадрово-независимым `1 - exp(-rate·delta)` + `physics/common/physics_interpolation=true`
  (устраняет лесенку трансформов при FPS≠60 — подозреваемый №1 для «дрожит»).

## Feel-чек заказчиком (живая игра)
1. Старт/стоп W при живом движении мыши: скольжения вбок нет, остановка строго прямая.
2. Резкий флик мыши + сразу W: траектория сразу туда, куда смотрит камера; корпус
   доворачивается с небольшим опозданием (это остаток C, не траектория).
3. Dodge/dash (Q/E, double-tap) после флика мыши — рывок по направлению взгляда.
4. «Дрожь» на старте/стопе при вашем FPS: осталась/уменьшилась — решить по итогу,
   включать ли physics_interpolation (задача C).

## Расследование «пропал блок» (закрыто заказчиком 9/10, БЕЗ изменений кода)
Симптом: при нажатии ПКМ «ничего не происходит», в логе нет оповещения о блоке.
Проверено (Q7.12 и Q7.11 идентичны):
- `sim_block.gd` 20/20 на обеих версиях — механика блока исправна: активация
  (заряд 0.217 с), окно 0.5 с, защёлка «1 нажатие = 1 блок», направленность
  (BLOCK_RESPONSE: LEFT↔RIGHT зеркально, UP↔UP), отражение урона, микро-стан врага.
- `sim_block_timing.gd`: окно нажатия ПКМ после телеграфа [0.03..0.65] с — в пределах реакции.
- Регрессии Q7.12 нет: diff версий = только movement-код + строка провайдера в сцене.
- Настройки блока в сцене дефолтные (переопределён лишь recovery_duration=0.15);
  в SettingsService блок-параметров нет.
Причина симптома (подтверждена заказчиком): пропало именно оповещение В ЛОГЕ.
След для протокола: строки `[Combat] BLOCK_INPUT_PRESSED/BLOCK_ACTIVATED` гейтятся
экспортом `debug_logging`, который управляется настройкой «Журнал боя [Combat]»
(SettingsService, секция «Разработка») и СТОЙКО хранится в `user://settings.cfg` —
однократное выключение гасит журнал во всех последующих сессиях.
Сам блок невидим by design (клипа Block в animation contract нет) — норма до
появления анимаций у заказчика. Никаких изменений кода не вносилось (D1–D4 отклонены).
Логи: `q_tools/sim_block_out.txt`, `q_tools/sim_block_timing_out.txt` (обе версии).
