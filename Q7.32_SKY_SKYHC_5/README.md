# Q7.32_SKY_SKYHC_5 — HighCloudLayer («вуаль»): этап SKYHC-5, фаза 5 ТЗ — интеграция с кучевыми облаками

Компонент-наследник `Q7.32_SKY_SKYHC_4`: копия папки + `sed` по путям + **новые uid**
(сгенерированы импортом Godot 4.7; дубликатов uid с SKYHC_1/2/3.1/3.2/3.3/4/D3 — 0).
Производство НЕ тронуто. `Q7.32_SKY_D3` сохранён (отдельная задача заказчика).

Задача: ТЗ «HighCloudLayer», **фаза 5** (п.1-5): подключить вуаль к итоговому изображению
в корректном порядке; проверить, что она не скрывает формы кучевых; отсутствие пересвета,
двойного затемнения и нежелательного изменения контраста; настройка визуального баланса;
независимое управление интенсивностью каждого слоя. Контрольная точка: «оба слоя
воспринимаются как части единого неба, но каждый выполняет собственную визуальную функцию».

## 1. Главный результат: шейдер НЕ изменён вовсе

Порядок композита «небо+солнце → ВУАЛЬ (дальше) → кучевые (ближе)» реализован в SKYHC-1
и осветлён в SKYHC-4; фаза 5 — ВЕРИФИКАЦИЯ взаимодействия числом (11 проверок HC5-*) и
инструменты A/B. 0 новых uniform'ов (22), 0 правок кода шейдера — только заголовочный
комментарий. Все замеры — на пресетах `preset_table()` и параметрах МАТЕРИАЛА (данные,
не хардкод): dp/lp/ap/su собираются из `.tres` и таблицы пресетов.

## 2. Численные результаты (сьют секция SKYHC-5; 3 пресета × 33 мировых луча)

| п.2 формы не скрыты | HC5-2 | за глухой плитой (T<0.05) вклад вуали подавлен до 2.2 % от чистого неба; контраст форм на плите C′/C = base/base′ ≥ 0.282 (порог 0.25) |
| п.3 нет двойного затемнения | HC5-3 | base′ == base·(1−α)+premult КОМПОНЕНТНО (1e-6): небо ослабляется вуалью ровно один раз, base′ кучевыми — ровно один раз, перекрёстных членов нет |
| п.3 нет пересвета | HC5-4 | под-аддитивность L_both ≤ L_veil+L_cum−L_bg: 0 нарушений на 99 кадрах (max excess 9.6e-5 — float32) |

| п.1 диск | HC5-7 | диск солнца/луны ослабляется вуалью строго (lum ниже) во всех трёх состояниях, пересвета диска нет |

**Форма-независимость и замер для заказчика** (HC5-10): вклад вуали Δ=(base′−base)·T
идентичен в GPU-форме `mix(base′, sub.rgb, sub.a)` и физической `base′·T + S` — интеграция
вуали не зависит от открытого вопроса SKYHC-1 §4. Само расхождение субпасс-формы для
КУЧЕВЫХ (S·(1−T) вместо S на тонких массах) измерено: max 0.099 lum (neutral, 5 тонких
лучей из 33) — компонент его НЕ правит (чужой контракт D-серии, вид принят в D2/D3);
данные для решения заказчика готовы.

## 3. Инструмент стенда: слоёвое A/B (строка меню «Слои A/B (пресеты)»)

4 состояния существующими uniform'ами (`HC_LAYER_PRESETS`): **Оба** / **Только кучевые**
(hc_enabled=false) / **Только вуаль** (cloud_coverage=1.0 + cloud_softness=0.01 →
плотность кучевых ≡ 0) / **Ни одного**. Почему не extinction_scale=0: при T=1 зеркала
продолжают накапливать рассеяние (S≠0) — GPU-форма его скрывает (alpha=0), зеркальная
нет — расхождение форм; coverage=1.0/softness=0.01 даёт плотность ≡ 0 в обеих формах
(проверено: T == 1.0 точно, HC5-9). Пресет перезаписывает ползунки «Количество облаков»/
«Размытость краёв» (0.23/0.17 — дефолты uniform'ов, сверяются сьютом со строками шейдера);
значение 1.0 вне диапазона слайдера 0.10-0.80 — отображение клампится, uniform остаётся 1.0
(подсказка меню предупреждает).

## 5. Что проверено в песочнице и что остаётся машине заказчика

Песочница (Godot 4.7-stable, headless, CPU): `--import` EXIT=0; сьют **203/203** (~16 с);
смоук сцены 90 кадров — 0 ошибок (меню со строкой «Слои A/B» собирается).

Машина заказчика (GPU) — контрольная точка фазы 5:
1. Меню (`9`) → «Вуаль» → «Слои A/B»: **Оба** → **Только вуаль** → **Только кучевые** →
   **Оба**: при возврате картина идентична (слои не влияют друг на друга — HC5-6), вуаль
   сидит ЗА кучевыми (кучи перекрывают её полосы, а не наоборот).
2. Контраст: кучевые сквозь вуаль не становятся «плоскими» — формы читаются (C′/C ≥ 0.28
   даже за глухой плитой; на тонких массах контраст снижается вуалью, не усиливается).
3. Пересвет: на закате (`F10`) вокруг солнца нет выбеленного ореола «двух слоёв» —
   под-аддитивность подтверждена числом (HC5-4).
4. Баланс: «Прямой свет вуали»/«Заливка неба вуали» (SKYHC-4) и «Плотность вуали»
   (hc_tau_per_km) подстраивают слой независимо от кучевых; у кучевых свои ручки
   (количество/размер/освещение) — вуаль на них не реагирует.
5. Ночь (`F12`): лунная вуаль ярче неба (доля до 0.72 на луче) — согласовано с кучевыми
   (тот же источник); тонкие кучевые на её фоне могут читаться темнее — легальная
   инверсия контраста (HC5-5), форма не исчезает.

## 7. Ограничения этапа и следующие шаги

1. Баланс-метрики считаются на зеркальном base (плоский sky_color + sun_bg) — GPU-градиент
   G(dir) богаче; доли яркости на GPU могут отличаться в пределах ±0.1, порядок и
   знаки выводов сохраняются (σ-структура и подавление плитой — геометрические факты).
2. Субпасс-расхождение кучевых (≤ 0.099 lum на тонких массах) — замерено, ждёт решения
   заказчика отдельным шагом (SKYHC-1 §4 → SKYHC-5 §2).
3. Далее **SKYHC6** = фаза 6 ТЗ: производительность и совместимость — замеры вкл/выкл
   вуали на GPU заказчика (full-res цена 2+1 texture3D-выборки на пиксель, POSITION →
   radiance cubemap, профили F6-F9, режимы рендера Forward+/Mobile), A/B
   `hc_use_world_anchor`; без замеров приростов не заявляем (ТЗ п.5). Затем **SKYHC7** =
   фаза 7: приёмка по чек-листу ТЗ + итоговый отчёт (файлы/координаты/параметры/проверки/
   ограничения).
4. Опции на решение заказчика (не блокируют): рецентринг cov_eff (3.2 §9), domain-warp
   детали (3.3 §7), HG-блик вуали у солнца (4 §6).
