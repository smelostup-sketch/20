# Диагностика: боковое скольжение и дрожь при старте/остановке движения
База: `Q7.11.RengarPreOmega` · Инструменты: `q_tools/diag_anim.gd`, `q_tools/diag_move.gd` · Логи: `diag_anim_out.txt`, `diag_move_out.txt`

## Вердикт
**Гипотеза «проблема с анимацией» НЕ подтверждена.** Анимационный слой измерен и чист.
Причина — в слое движения/поворота: два доказанных механизма (A, B) + один рендер-подозреваемый (C).

## Доказательная база

### 1. Анимация невиновна (diag_anim.gd + зонд)
| Проверка | Результат |
|---|---|
| Root motion / треки корневого узла в клипах | Отсутствуют — все треки на костях `Skeleton3D`, узел `VisualModel` неподвижен (`modelOff` константа во всех сценариях) |
| Латеральное движение Hips в клипах | Idle: X ±0.6 см; Run: X [−0.64..+1.23] см — естественный цикл, не дрейф |
| Позовый «щелчок» при hard-cut Idle↔Run | ≤ 9 мм по Hips (T=92→93: 7 мм; T=205→206: 9 мм) — микро-рывок, не скольжение |
| Флип-флоп анимаций (порог 0.15 м/с) | Нет: ровно одно переключение на старт и на стоп |
| Пол / `is_on_floor()` | 0 миганий за 320 тиков; `vel.y` = 0 всё время на земле; Y-позиция тела константа |

### 2. Механизм A — направление движения считается из ОТСТАЮЩЕЙ базы тела (ДОКАЗАНО)
- `StateComponent.apply_physics()`: `target_dir = owner_body.global_transform.basis * input_dir`.
- Тело поворачивает `ThirdPersonCamera._process()`: `rotation.y = lerp_angle(rotation.y, yaw, 12.0 * _delta)` — тело догоняет камеру с лагом (τ ≈ 83 мс и больше).
- Камера в игре ВСЕГДА живёт от мыши → в момент нажатия W расхождение yaw/тела практически гарантировано.
- Сим `MOUSE_OFFSET` (+35° на тике 140, W зажат): тело догоняет yaw ~20 тиков; всё это время вектор скорости догоняет вращающуюся цель → **траектория изгибается: латеральное смещение −0.87 м за 0.42 с, угол(скорость, фейсинг) до 14°**. Это и есть «скользит влево/вправо, потом выравнивается».
- Сим `STRAIGHT` (мышь неподвижна): латеральное отклонение **0.00000 м** за 320 тиков — без расхождения код идёт идеально прямо. Значит триггер — именно расхождение yaw/тела.

### 3. Механизм B — поосевое торможение `move_toward` КРИВИТ направление (ДОКАЗАНО)
```gdscript
velocity.x = move_toward(velocity.x, 0.0, braking_rate * delta)
velocity.z = move_toward(velocity.z, 0.0, braking_rate * delta)
```
Компоненты X и Z гасятся независимо и линейно → меньшая компонента умирает раньше → **вектор скорости при торможении поворачивает к доминирующей оси**. Замер в стоп-фазе (T=230..250): угол(скорость, фейсинг) растёт 0.6° → 2.1° → 4.1° → 13.7° → **35°** — персонаж при остановке едет боком («конькобежец»), пока скорость не упадёт ниже 0.15 м/с и не включится Idle. Run-анимация продолжает играть всё торможение (0.33 с от 6 м/с) — визуально усиливает скольжение.

### 4. Механизм C — «дрожит» (подозреваемый; headless не меряет рендер-кадры)
- Physics interpolation в `project.godot` НЕ включена (дефолт off) → при FPS ≠ 60 трансформы тела обновляются лесенкой 60 Гц, камера в `_process` следует за лесенкой → темпоральный джиттер, максимально заметный именно на разгоне/торможении (производная скорости меняется).
- Поворот тела делается в `_process` (рендер-рейт), а цель скорости сэмплируется в `_physics_process` → физический тик видит неравномерные приращения yaw. Замер: +8.00°, +4.28°, +5.19°, +2.79°, +2.33° за тик — траектория во время доворота получает микро-рыскание.
- `lerp_angle(…, 12.0 * _delta)`: при дельте > 83 мс (FPS < 12, фризы) вес > 1 → перелёт за цель → осцилляция. Плюс сглаживание кадрово-зависимое (не `1 - exp(-k·delta)`).

## План фикса (компонентно, без хардкода)
- **A. Направление — из намерения камеры, не из отстающей базы.** Единый источник yaw (камера уже отдаёт `get_view_yaw()`); в `StateComponent` — опциональный провайдер (экспорт), у врага fallback на собственную базу (owner-agnostic, как ядро атаки). Траектория = ровно туда, куда смотрит камера; доворот тела становится чисто визуальным.
- **B. Векторное торможение/разгон:** `Vector2(vx,vz).move_toward(target, rate*delta)` — одна ветка вместо двух, направление не искажается ни на разгоне, ни на стопе.
- **C. Поворот тела — в `_physics_process`, кадрово-независимо:** `1.0 - exp(-rate * delta)`, rate — экспорт с калибровочным комментарием (замер инструментом diag_move). Проектно: `physics/common/physics_interpolation=true` — feel-чек заказчиком в живой игре.
- **D. (косметика, опционально)** Кроссфейд локомоции `play(clip, 0.1)` — гасит позовые щелчки ≤ 9 мм; method track'и атак не затрагивает (они в one-shot клипах).

Критерий приёмки (повторный прогон `DIAG_SCENARIO=MOUSE_OFFSET`): латеральное отклонение траектории от направления камеры ≤ 1 см; угол(скорость, фейсинг) в стоп-фазе ≤ 5°; STRAIGHT/IDLE остаются нулевыми; `sim_core` 12/12.

## Побочные находки (в очередь «чистка мусора»)
- `VisualModel_AnimationPlayer` в `Основная_сцена.tscn`: `root_node="../VisualModel"` разрешается в несуществующий путь; узел никем не используется (компоненты берут `AnimationPlayer` из FBX) — мёртвый узел.
- Шов цикла Running.fbx: Hips X прыгает 1.23 см → −0.64 см каждые 0.633 с (LOOP_LINEAR) — малозаметно, но измерено.
- Скорость Run-анимации не связана с фактической скоростью движения (нет blend/параметра) — тема на будущее ( feel).
