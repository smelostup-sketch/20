# ПРОМТ / ТЗ: Стилизованная система неба, облаков, солнце/луны и единого освещения земли

## 0. Контекст и цель

Проект — стилизованная (живописная / аниме-концепт) игра. Небо, облака и освещение должны выглядеть как живописные референсы заката/сумерек/ночи, а не как фотореализм.

**Проблема, которую решаем:** ранее небо жило своей жизнью — 20+ прогонов без сходимости. Причина: не было единого источника цвета. Небо красилось из одной палитры, а свет земли — отдельно (белый статичный DirectionalLight + рантайм-IBL). Облака выглядели как статичные наклейки. Вуаль была однотонной по всему куполу. Солнце/луна не были увязаны с палитрой.

**Цель:** построить систему, где **одна таблица состояний (LUT) кормит всё** — небо, облака, солнце/луну/звёзды и свет земли (key/fill/bounce). Рассинхрон «багровое небо / белая земля» должен стать *конструктивно невозможен*, потому что другого источника цвета физически не существует.

**Стек:** Godot 4 (DirectionalLight3D, Environment/Sky, sky-шейдер, шейдерные параметры). Рендер — стилизованный, НЕ честный PBR с HDRI.

---

## 1. Фундаментальный принцип: единый источник правды

Есть одна угловая палитра состояния `P(dir)` и одна таблица из 7 ключей по высоте солнца `elev`. Из них предвычисляются/семплируются цвета для всех подсистем. Никаких «дефолтных серых ambient», «белого ключа», «HDRI-куба по умолчанию».

```
LUT состояния (7 ключей по elev солнца)
   │  данные ключа: zenith/mid/horizon/sun_glow + cloud(lit/shadow/rim/under)
   │                + veil(*) + sun_disc(*) + moon(*) + star + производные земли
   │
   ├──► небо:        градиент купола P(dir) + вуаль(из того же P) + диск/ореол
   ├──► облака:      зонная покраска через масок-пак (lit/shadow/rim/under)
   ├──► солнце/луна: аналитический диск/серп + ореолы + звёзды
   └──► свет земли:  KEY (DirectionalLight) / FILL (IBL-кубмапа неба) / BOUNCE (нижний свет)
         ▲
         └── все ветки читают ОДНУ таблицу в ОДНОЙ функции _apply_t(t)
```

Меняется состояние → интерполируется одна LUT → синхронно едут небо, облака, диск и наземный свет.

## 2. Состояния: 7-ключевая лестница по elev солнца

Ключи упорядочены по физической оси `elev` от ночи к дню. Интерполятор `_apply_t(t)` лерпит соседние ключи. Все референсы (старые «закатные» O1–O5 и новые «ночные» N1–N5) переразмечены по этой лестнице.

| Ключ | Состояние | elev солнца | Hero-реф | Supporting-рефы |
|---|---|---|---|---|
| K0 | Глубокая ночь (индиго) | < −18° | N2 (полная луна, лунная дорожка) | N4 |
| K1 | Астрономические сумерки | −15…−12° | N4 (звёзды+метеор, синий→бирюза→фиолетовый) | N3 (верх) |
| K2 | Синий час / гражданские сумерки | −6…−4° | N5 (индиго→фиолетовый→розовый горизонт) | N3 (низ), N1 (розовая полоса) |
| K3 | Контровой закат (солнце за облаком) | −2…0° | O1 | N1 (солнечный узел над морем облаков) |
| K4 | Багровый/золотой закат (диск на горизонте) | 0…+1° | O4 (багровый) | O2 (золотой с глэйром) |
| K5 | Золотой час | +2…+6° | O3 (солнце справа) | — |
| K6 | Поздний день / пастельный зенит | +10…+20° | O3 (зенит) + O5 (дневной кучевой) | N1 (дневной синий зенит) |

*(O1–O5 = первые 5 референсов-закатов; N1–N5 = 5 новых ночных/сумеречных, в порядке прикрепления.)*

**Критично:** новый стоп `mid` (фиолетовый/пурпурный средний пояс) обязателен для K1–K3 — без него интерполяция K2↔K3 (фиолетовый → оранжевый) даст грязь. Рефы N3/N4/N5 вводят фиолетовый пояс и бирюзовые акценты, которых не было в закатных рефах.

## 3. Небо: угловая палитра P(dir) + вуаль из той же P

### 3.1. Градиент купола — многостопный рамп (НЕ два цвета)
```
P(dir) = ramp_by_height(dir.y)            // 3+ стопа: zenith → mid → horizon
       + sun_term(dot(dir, sunDir))        // горячий узел у солнца/зари
       // антисолярный зенит остаётся тёмным самим zenith (не осветляем)
```
`ramp_by_height` — 1D-текстура-рампа на состояние (zenith/mid/horizon). `sun_term` — `sun_glow_col * pow(max(dot(dir,sunDir),0.), sun_exp)`.

### 3.2. Вуаль (haze) — берёт цвет от ВСЕЙ палитры, сила зависит от высоты и солнца
**Правильная модель (утверждена):** вуаль семплит ту же `P(dir)`, что и небо, но чуть высветленную/утеплённую, с маской по высоте и солнцу. Однотонная или двухцветная вуаль ЗАПРЕЩЕНА — она убьёт фиолетовый средний пояс рефов N3/N5 и тёмный антисолярный зенит.

```glsl
vec3 Pdir        = P(dir);                                  // тот же цвет, что у неба в этой точке
vec3 veil_col    = Pdir * veil_lift + veil_warm;            // чуть светлее/теплее
float height_mask = 1.0 - pow(saturate(dir.y), veil_curve); // 1 у горизонта, 0 в зените
float sun_mask   = 1.0 + veil_sun * pow(max(dot(dir,sunDir),0.0), veil_sun_exp);
float veil_a     = height_mask * sun_mask * veil_master;
vec3 final_sky   = mix(Pdir, veil_col, veil_a);             // вуаль поверх неба
```

Поведение, которое должно получаться:
- **Антисолярный зенит:** `dir.y` велик → `veil_a ≈ 0` → вуали нет, тёмный индиго `P` чистый. ✔
- **У солнца/зари:** `dot` велик → `veil_a` растёт, `veil_col` светлый/тёплый → раскалённая дымка. ✔
- **Между ними:** `P(dir)` проходит через фиолетовый `mid`-стоп, вуаль его повторяет → средний пояс сохранён. ✔
- **Ночь K0:** `veil_master → 0` → зенит чистый, звёзды не гаснут. ✔

## 4. Облака: карточки/импосторы с масок-паком + оживление
> **ОТМЕНЕНО решением заказчика 25.10.26: облаков-карточек НЕ будет.** Раздел 4, таблица
> §8.3, шаг §10.7 и зависящие тесты (§11.4 в части облаков, §11.7) недействительны;
> масок-пак не требуется. Единственный облачный слой проекта — вуаль на P(dir).

### 4.1. Ассет-контракт (масок-пак, один файл = одно облако)
Каналы: **A** = альфа силуэта (crisp, ядро кромки 1–3 px, без тёмного гало, defringe; straight alpha, не premul), **R** = form/зоны (полный диапазон 0.1–1.0, плато: тень 0.30–0.45 / свет 0.70–0.85 / блик 0.95+; мягкость только внутри тени), **G** = rim-маска (прерывистая, ТОЛЬКО солнечная верхне-левая кромка + 2–3 выступа; НЕ замкнутый контур), **B** = under-маска (низ, спад ограничен нижними 20–30% высоты, без дыма в середину). Свет при покраске зон фиксирован: слева-сверху ~40°.

Формат: PNG/TGA RGBA, 2048 hero / 1024 mid-distant, padding ≥ 32 px, бесцветный рабочий пак (цвет — из LUT, не запекать). Отдельно — превью в 3 палитрах (закат, сумерки, ночь). Блёстки/искры в текстуру НЕ запекать.

Набор: `hero_tower` (эталон финиша), `hero_mass` (рамочная масса с окном), `cumulus_mid ×3`, `cumulus_small ×3`, `cirrus_stripe ×2` (бесшовные по X), `cloudsea_tile` (бесшовный по X ковёр).

### 4.2. Стилизованный шейдинг облака (терминатор заостряется шейдером из R)
```glsl
float n   = snoise(vec3(uv*2.0, _Time.y*0.05 + seed));     // ползущий терминатор
float lit = smoothstep(termA + n*0.06, termB + n*0.06, R); // crisp-зоны из мягкой R
vec3 col  = mix(cloud_shadow, cloud_lit, lit);
col += cloud_rim  * G * glint;                              // мерцание кромки
col += cloud_under * B * sunBelow;                          // подсветка низа на закате
// воздушная перспектива: подмешать horizon-цвет неба в тень по дистанции
// soft-intersection fade на пересечениях с другими карточками/геометрией
```
Все цвета (`cloud_lit/shadow/rim/under`) — из LUT текущего состояния.

### 4.3. Оживление («анти-наклейка»), пакет приоритетов
**P0 (дёшево, убирает наклейку):**
- Boil / стоп-моушен warp: `t = floor(time*boilFps)/boilFps; uv += (snoise(...)-0.5)*boilAmp;` — форма «кипит» как живая краска. `boilFps 2–4`, `boilAmp 0.004–0.008`.
- Дрейф по ветру + per-instance random (фаза/скорость ±20%/масштаб ±10%) — копии рассинхронны.
- Ползущий терминатор (см. выше).
- Дыхание трансформации: scale 1±0.01, наклон ±1–2°, период 8–15 с.

**P1 (свет играет):** мерцание rim (`glint = pow(max(snoise(uv*9, time*0.6+seed),0.0), 6.0)`), воздушная перспектива по дистанции, soft-intersection fade.

**P2 (герои):** двухслойная карточка (front/back, back скроллится/warp'ится медленнее → внутренний параллакс), морф силуэта A↔B пинг-понгом 25–40 с, опционально flipbook 8–12 кадров для 1–2 героев, отрывающиеся дымки (GPU-партиклы с кромки), sparkle-мотки (additive, те самые блёстки из рефов — отдельным слоем).

**P3:** порывы ветра (анизотропный warp вдоль ветра), отклик на смену состояния (терминатор/under «переезжают» за 5–10 с).

**Дисциплина амплитуд:** boilAmp 0.004–0.008 (больше = медуза), boilFps 2–4 (>6 = желе, стиль умирает), терминатор-шум ±0.04–0.06, дыхание ±1%/±1–2°, glint редкий pow≥6, дрейф 0.5–2°/мин.

## 5. Солнце и Луна: аналитика в sky pass, НЕ карточки

### 5.1. Солнце — аналитический диск + ореолы, два прохода
**Sky pass (до облаков, перекрывается ими):**
```glsl
float ang  = acos(clamp(dot(dir, sunDir), -1.0, 1.0));
float edge = max(fwidth(ang)*1.5, 0.0004);                 // AA кромки на любом разрешении
float disc = 1.0 - smoothstep(sunR-edge, sunR+edge, ang);  // crisp-диск, sunR художественный 1.5–2.5°
float d    = max(dot(dir, sunDir), 0.0);
vec3 sun   = discCol*disc*coreInt
           + g1Col*pow(d,g1Exp)*g1Int                       // средний ореол
           + g2Col*pow(d,g2Exp)*g2Int;                      // широкое поле (до облаков)
sky += sun;
```
Опциональный squash у горизонта (scale Y до 0.85 при elev<3°). Цвет диска краснеет к закату через кривую по elev.

**Post pass (после облаков, аддитивно, screen-space, без глубины):** широкое свечение + стрики — именно оно обтекает облака (реф O1: солнце скрыто, но небо в свете).
*Примечание 25.10.26: облака отменены — обтекать нечего; стрики реализованы v1 в sky pass (угловой спрайт), screen-space post-pass избыточен. Тонмаппер-bypass выполнен display-композитом (§10.8).*
```glsl
float dd = length((uv - sunScreen)*aspectFix);
vec3 wide = gWideCol*exp(-dd*wideFalloff)*wideInt*broadVisibility;
wide += streakCol*streakSprite(uv, sunScreen, streakRot)*streakInt;  // рисованный glare (ассет)
frame += wide;   // после тонмаппера неба или с bypass-флагом
```
`broadVisibility` — мягкая кривая по elev (не бинарная!). Стрик-спрайт — единственный новый ассет по солнцу (horizon-glare для K4-золотого).

### 5.2. Луна — SDF-фаза, НЕ карточка и НЕ атлас фаз
```glsl
vec2 p  = moonBasisUV(dir);                                 // направление в базисе луны
float w = edgeW;                                            // crisp через fwidth
float body = 1.0 - smoothstep(-w, w, length(p) - r);
float cut  =        smoothstep(-w, w, length(p - phaseOff) - r*0.98);
float crescent   = body * cut;
float earthshine = body * (1.0-cut) * 0.06;
float md = max(dot(dir, moonDir), 0.0);
vec3 moon = moonCol*(crescent + earthshine*earthCol)
          + moonGlowCol*pow(md, moonGlowExp)*moonGlowInt;
sky += moon;   // sky pass: облака перекрывают луну корректно
```
`phaseOff` = фаза 0..1 (анимируема сюжетно), сторона растущая/убывающая — знак смещения. Кромка серпа crisp. Деталь (кратеры) — опциональная рисованная маска в `body` только для полных фаз. **Звёзды локально гасятся:** `starInt *= 1 - moonGlowMask*0.7`. Луна не «кипит» (небесное тело статично-чёткое), допустимо лишь медленное мерцание широкого ореола ±3%.

**Почему не карточка:** тонкий серп исчезает/jaggies на mip-цепочке альфы; фазы бесплатны параметром; нет сортировки и памяти; crisp-кромка по контракту стиля.

### 5.3. Tonemapper (ВАЖНО, общая грабля)
Диск и ореолы — в display-space или с **bypass тонмаппера**, иначе ACES/Filmic уведут багровое свечение в бурое и десатурирует закаты. Bloom: порог ~1.0, `coreInt` 4–8 (контролируемый глянец, не каша). То же правило bypass — к финальному грейду сцены, чтобы небо и земля не разъехались по цвету.

## 6. Освещение земли: три компонента из той же LUT

**Источник света = состояние неба целиком.** Солнце/луна — лишь маркер направления. Три компоненты, все из `_apply_t`:

| Компонента | Направление | Цвет (из LUT) | Реализация Godot |
|---|---|---|---|
| KEY | sunDir (тот же вектор, что у диска) | `key = norm(sun_glow/lit)`, `key_energy = max(lit)*KEY_SCALE` | DirectionalLight3D.light_color/energy |
| FILL | сверху (мягкий) | `fill = lerp(zenith, mid, 0.5)` | IBL-кубмапа неба (см. §7) |
| BOUNCE | снизу | `bounce = horizon * BOUNCE_SCALE * groundTint` | второй DirectionalLight3D снизу-вверх, energy 0.3–0.5, БЕЗ теней |

Земля на полтона-тон спокойнее и чуть менее насыщена, чем небо (небо — витрина, земля — сцена). Тени уходят в холодный комплементарный hue относительно тёплого ключа (закат оранжевый → тень сине-фиолетовая) — тени НЕ чёрные и НЕ нейтрально-серые.

**Tonemap-нюанс земли:** M1-значения scene-referred (horizon=2.0 и т.д.), а `light_color` — sRGB Color с clamp до 1.0. Поэтому hue кладётся нормированным (`col/col.max()`), а HDR-плечо уходит в `light_energy`/масштаб. `Vector3(2.0,…)` напрямую в Color класть НЕЛЬЗЯ.

**Направление key == sunDir неба обязательно** (иначе диск и тени смотрят в разные стороны). Жёсткость теней по elev: высокое солнце → короче/жёстче, закат → длинные мягкие; в стилизации часто мягкие blob-тени вместо резких каскадов.

## 7. IBL (fill): оставляем, лаг чиним способом 1

Fill земли = radiance-кубмапа, которую генерирует sky-шейдер (`ambient_light_source = SKY`). **Оставляем IBL** (вуаль и гало живут в тенях — это ценно). Проблема — лаг `PROCESS_MODE_INCREMENTAL` (кубмапа догоняет небо с задержкой при смене состояния).

**Решение — способ 1 (форс-обновление), с оговоркой про непрерывную интерполяцию:**
- Поскольку `_apply_t` лерпит ключи *непрерывно*, «момент смены» = весь интервал движения. Форсить нужно **каждый кадр, пока идёт интерполяция** (флаг `is_transitioning`), в статике у ключа — `INCREMENTAL`.
```gdscript
# в _apply_t, пока is_transitioning:
sky.process_mode = Sky.PROCESS_MODE_REALTIME   # полная пересборка кубмапы этот кадр
# в статике у ключа:
sky.process_mode = Sky.PROCESS_MODE_INCREMENTAL
```
- **Проверить, что рендерится в sky cubemap:** если только градиент+диск → REALTIME дёшев. - **Резерв (вариант B,** если даже упрощённый IBL не устроит по цвету теней): `ambient_light_source = COLOR`, `ambient_light_color = fillCol`. Детерминированно, без лага, но вуаль/гало перестанут влиять на землю. Держим в запасе.

## 11. Тесты приёмки

1. **Единый источник (главный тест):** выключить рендер неба → земля освещена key/fill/bounce из LUT → должна читаться как то же состояние (K0 — холодная лунная, K4 — багровый закат, K2 — фиолетово-розовые сумерки) по hue теней и балансу. Включить небо → оно совпадает по hue-семейству с землёй (deltaE по hue мал, разница в value/saturation). До правок проваливался (белый ключ 2.2 на багровом небе).
2. **Вуаль:** антисолярный зенит тёмный и чистый (ночью звёзды не гаснут); у солнца/зари — раскалённая дымка; фиолетовый средний пояс K1–K2 сохранён под вуалью.
3. **Кромка диска/серпа:** на 1080p и 4K без лесенки и без мыла (fwidth-AA).
4. ~~**Окклюзия:** солнце за `cloudsea_tile` (K4)…~~ НЕДЕЙСТВИТЕЛЕН (облака отменены 25.10.26); остаётся проверка: вуаль ослабляет диск честно (1−veil_a).
5. **Цвет ореола:** пипетка по ореолу в K4 совпадает с палитрой рефа O4 (deltaE < 6).
6. **Луна и звёзды:** вокруг серпа/диска звёздное поле приглушено, вне ореола — полное.
7. НЕДЕЙСТВИТЕЛЕН (облака-карточки отменены 25.10.26).
8. **IBL-лаг:** при переходе состояния тени на земле не «догоняют» небо с задержкой.
9. **Интерполяция стыков:** автопрогон K0↔K1↔K2↔K3↔K4↔K5↔K6 — на стыках (особенно K2↔K3, K0↔K1) нет грязных зелёных/бурых hue-сдвигов; при грязи — добавить промежуточный под-ключ.
10. **Переходы солнца/луны:** интерполяция размера/фазы без скачков; серп не «хлопает» при смене фазы.

## 12. Чего НЕ делать (антипаттерны)

- Не брать ambient из дефолтного серого/чёрного или HDRI «по умолчанию» — мгновенный рассинхрон с небом.
- Не делать тени чёрными/нейтрально-серыми — тень = холодный комплементарный из LUT.
- Не отвязывать направление key от sunDir неба ни на градус.
- Не освещать землю тем же HDR-интенсивным солнцем, что рисует диск — наземный key приглушён.
- Не пускать диск/ореолы/финальный грейд через ACES без bypass — багровое станет бурым.
- Не брать физическую интенсивность солнца (тысячи кандел) и «честный» bloom — белёсое пятно вместо диска.
- Не рисовать солнце/луну спрайтом-билбордом в геометрии — алиасинг кромки + сортировка против облаков; только аналитика в sky pass.
- Не давать луне мыльный край и «детскую» растушёвку серпа.
- Не делать вуаль однотонной или двухцветной по куполу — только из общей `P(dir)` с масками.
- Не класть `Vector3(2.0,…)` напрямую в `Color` — нормировка hue + scale в energy.
- Не запекать финальный цвет и блёстки в облачные текстуры — цвет из LUT, блёстки отдельным партикл-слоем.
- Не использовать PBR-набор карт (normal/roughness/metallic/specular) для облаков — в стилизованном пайплайне не нужны.

## 13. Итоговая архитектура (одна картинка)

```
_apply_t(t): интерполяция 7-ключевой LUT по elev солнца  ← ЕДИНСТВЕННЫЙ источник цвета
   │  данные: zenith/mid/horizon/sun_glow · cloud(lit/shadow/rim/under)
   │          veil(6) · sun_disc(3) · moon(3) · star · производные земли
   │
   ├─► купол неба        P(dir) = ramp(zen/mid/hor) + sun_term          ✅
   ├─► вуаль             из той же P(dir), маски высота+солнце          ✅ (починить)
   ├─► диск + ореолы     sun pass + post wide-glow/streak               ✅
   ├─► луна + звёзды     SDF-серп + glow, звёзды с damping              ✅
   ├─► облака-карточки   ОТМЕНЕНО заказчиком 25.10.26 (масок-пак не нужен)  ❌
   ├─► KEY земли         DirectionalLight.color/energy ← lit            🆕
   ├─► FILL земли        IBL-кубмапа неба (способ 1, без лага)          🔧
   └─► BOUNCE земли      DirectionalLight снизу ← horizon               🆕
```

Шесть+ веток, одна таблица из 7 строк, одна функция `_apply_t`, один интерполятор. После сборки рассинхрон «небо живёт своей жизнью» исчезает конструктивно — итерации наконец начинают сходиться, потому что крутится одна таблица, а не четыре несвязанных места.
