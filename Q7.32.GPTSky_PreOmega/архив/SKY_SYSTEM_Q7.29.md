## 3. Архитектура (коротко)

- **Шейдер** — вся визуальная математика; 8 логических секций комментариями.
  Точка входа `void sky()` (Godot 4.x!), направление — built-in `EYEDIR`,
  вывод — `COLOR` (vec3). Направление НЕ из камеры/луны; время НЕ из TIME.
- **Контроллер** — единственная логика времени: enum Phase {SUNSET, TWILIGHT,
  NIGHT} (без DAY), автопрогресс с dwell-временами (300/180/0=∞), loop
  опционален, внешние `transition_to()`/`set_phase_instant()`, ОДИН активный
  переход (перезапуск стартует с текущих значений — без гонок твинов),
  easing smoothstep, длительность 0 = мгновенно, epsilon-гейт записи в материал.
  Движение облаков: контроллер накапливает Vector2-офсеты на CPU (GDScript
  float = double → нет дрейфа за длинные сессии) по delta → fps-независимо;
  направления/скорости двух слоёв независимы (данные в профилях).
- **Профили фаз (.tres)** — данные, не код: все динамические uniform'ы + свет
  (цвет/энергия/направление) + ambient_energy. Палитры градиента (9 цветов) —
  художественные константы материала; фазы смешиваются весами
  sunset_amount/night_amount (их тоже хранят профили). Уточнение к предложенным
  именам промта: вместо 4 цветов палитры — 3 стопа на фазу (horizon/mid/zenith
  × 3 фазы) — иначе «трёхполосный градиент с видимыми границами», запрещённый
  §4.1. `cloud_wind_*` переехали из шейдера в профили/контроллер (шейдер
  получает готовые офсеты — требование «controller-driven offset», §5).
- **Качество** — один шейдер, uniform `quality_detail`: 0=Performance (без
  detail-слоя, без второго слоя облаков, без внешнего гало), 1=Quality.
  Uniform-ветвление одинаково для всех пикселей кадра (нет wave-дивергенции),
  но экономит сэмплы текстур. Бенчмарки НЕ ВЫДУМАНЫ: процедура — в п.8.
- **Свет** — существующий DirectionalLight3D основной сцены переиспользован
  (второй источник НЕ добавлялся): закат — тёплый (1.0, 0.62, 0.35) @ 2.2,
  низкий (euler −25°); сумерки — фиолетовый @ 0.7; ночь — холодный лунный
  (0.62, 0.70, 0.95) @ 0.45, euler (−33, 155, 0) ≈ направление луны в шейдере
  (0.35, 0.55, −0.75) — согласованы. Луна в шейдере НЕ освещает сцену (§4.3).
- **Radiance** — `Sky.process_mode = INCREMENTAL (2)`: cubemap окружения
  обновляется растянуто по кадрам. REALTIME не форсирован (стоимость: полная
  перерисовка cubemap каждый кадр при минутных изменениях — неоправданно).
  Ограничение: ambient/отражения отстают от видимого неба на доли секунды —
  для переходов 20+ с незаметно.

## 4. Как открыть и посмотреть

1. Открыть проект в редакторе (импорт platforma4k.glb и trava2 пройдёт сам).
2. **Тест-сцена**: запустить `Сцена_неба.tscn` (F6). Клавиши: `1/2/3` —
   плавные переходы закат/сумерки/ночь (3 с); `4/5` — покрытие облаков
   0.05/0.85; `6/7` — ветер ×0.2/×3; `8/9` — Performance/Quality; `0` —
   автопрогресс. Состояние — в Label слева вверху.
3. **Основная сцена**: контроллер уже подключён, автопрогресс ВКЛЮЧЁН
   (закат 300 с → сумерки 180 с → ночь ∞). Быстрый осмотр: у
   TimeOfDayController вызвать в Remote-инспекторе `set_phase_instant(2)`
   или временно уменьшить `transition_duration`.

## 5. Ручные настройки в инспекторе (если потребуется)

- `TimeOfDayController` (обе сцены): sky/light_path/environment/профили/
  quality — назначены; при переносе узлов перепривязать `light_path`.
- Палитры фаз — в `omega_sky_material.tres` (9 цветов) — художественная зона.
- Импорт шумовых PNG оставлен дефолтным (VRAM Compressed + mipmaps). Нюанс:
  sRGB-декодирование монотонно сдвигает средние тона шума — компенсировано
  параметрами coverage/density; при желании «чистых данных» — переключить
  режим сжатия на Lossless (потеря VRAM несущественна для 2×1024²).

## 6. Внешние ассеты

Не требуются: обе шумовые текстуры сгенерированы детерминированно
(`q_tools/gen_cloud_noise.gd`, воспроизводимо байт-в-байт). Подмен
нерелевантных картинок нет, пустых плейсхолдеров нет. Метод: периодический
value-noise FBM на завёрнутой решётке (бесшовность математическая), quintic-
сглаживание, контраст вокруг 0.5. Почему не FastNoiseLite.seamless: у
FastNoiseLite в Godot 4.7 свойства seamless НЕТ (проверено рантайм-ошибкой),
а генерация NoiseTexture2D в headless ненадёжна.

## 10. Известные ограничения и следующие шаги

1. **Визуал не проверен пикселями** (headless): плавность градиентов, вид
   облаков, луна/звёзды — приёмка заказчиком в Сцена_неба.tscn.
2. GPU-компиляция шейдера — на машине заказчика (парсер headless её не
   выполняет; синтаксис проверен парсером движка 4.7).
3. Звёзды статичны (без мерцания) — дёшево; мерцание можно добавить uniform'ом
   при желании.
4. Радиance INCREMENTAL: отражения в глянцевых материалах обновляются с
   небольшой задержкой — для минутных фаз незаметно.
5. Погода (гроза/шторм из визуального брифа) НЕ внутри контроллера суток —
   следующий отдельный слой (промт §7).
6. Облака — 2D-слоистая имитация глубины (масштаб/движение/шейдинг), НЕ
   volumetric ray-marching (по контракту первой версии).
7. Шумовые PNG при импорте проходят sRGB-декод (дефолт): монотонный сдвиг
   средних тонов учтён настройкой coverage/density; при желании — Lossless.
