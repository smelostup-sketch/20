## 1. Видение заказчика (дословно, ночная сессия 13.10.2026)
«Сделаем врага настолько адаптивным и умным, что он начнет наугад бить куст,
когда игрок зайдет в него и скроется от врага, или станет патрулировать вокруг
куста, дожидаясь игрока. Если же будет сильно ранен и не будет уверен в победе,
попытается сам скрыться от игрока, спрятаться.»

## 2. Декомпозиция на шаги (каждый — отдельная версия с симами и feel-чеком)
### B1. Читаемые паттерны атак + ритм (чистый мозг, без новых сенсоров)
- pattern_length 2–3 (движок УЖЕ встроен в Фазе A: profile.pattern_length;
  структура «серия повторов с редкой сменой» — добавить chance-ручку смены).
- Ритм (L4, дуэльный режим): attack_interval ± разброс вместо «бей сразу после
  recovery» — давление дозированное; tokens_per_window=1 в дуэли (координатор
  толпы — отдельным шагом, когда появятся группы; НЕ autoload — урок GameLog).
- Ручки: pattern_length, pattern_switch_chance, attack_interval_min/max.
- Стенд: sim_ai_duel (часть 1) — фиксированный сид: враг повторяет направление
  pattern_length раз; игрок «наказывает повтор» (сценарий: после N одинаковых
  атак враг обязан сменить направление).

### B2. Отход после стана + блок с бюджетом реакции
- Отход: подписка stun_started уже есть (Фаза A) — добавить состояние AFTER_STUN:
  RETREAT на post_stun_retreat_time (ручка), направление «от игрока» БЕЗ utility
  (сейчас retreat_dir приходит только из utility — добавить fallback в мозге).
- Блок врага: block_chance + reaction_ms (ручки); честная схема: perception видит
  старт анимации атаки игрока (attack_performed) -> задержка reaction_ms ->
  activate_enemy_block(направление): угадывание = BLOCK_RESPONSE[атака игрока]
  с вероятностью block_dir_guess_chance, иначе случайное. Разрешение блока —
  то же ядро (is_blocking_active), наказание игрока за заблокированный удар —
  как у врага (стан? — ОТКРЫТЫЙ ВОПРОС 4).
- Стенды: sim_ai_duel (часть 2): block_chance=1.0, reaction_ms=0 -> враг блокирует
  телеграфированную атаку игрока (hp врага цел); block_chance=0 -> не блокирует.

### B3. Куст: расследование, патруль, слепой удар
- Честный сенсор «потерял игрока»: в рамках игровой абстракции стелс = «исчез из
  чувств». Perception: last_seen_position + since_seen (обновляется, пока игрок
  виден = dist <= detection_range и НЕ в стелсе; в момент исчезновения фиксируем
  последнюю видимую позицию — это честно: враг видел, куда игрок вошёл).
- Новые состояния мозга: INVESTIGATE (идти к last_seen), SEARCH (патруль-орбита
  вокруг last_seen радиусом patrol_radius), AMBUSH_WAIT (держать край куста),
  BLIND_STRIKE (удар «в куст» с вероятностью blind_strike_chance когда рядом).
- Новые move_state -> AIIntent: steering орбиты (касательный вектор вокруг точки)
  и «к точке» — те же direction/speed_scale в MovementIntent, исполнитель прежний
  (MovementShell + GroundLocomotion) — единообразие сохраняется.
- Выход из поиска: игрок снова видим -> обычные решения; search_time истёк ->
  IDLE/возврат к точке патруля (ручка).
- Стенд: sim_ai_bush (сид): игрок входит в куст -> стелс -> враг идёт к последней
  видимой точке, патрулирует, (опционально) бьёт вслепую; игрок выходит -> CHASE.

### B4. Самосохранение: бегство и укрытие (РЕВИЗИЯ 17.10.2026 по вердиктам заказчика)
- Триггер: hp_ratio < flee_hp_threshold И «не уверен в победе» = честная оценка:
  соотношение hp + статистика Memory (доля моих атак, которые игрок заблокировал/
  уклонился; агрессивность игрока). Формула уверенности — данные/ручки, не магия.
- Поведение: FLEE (RETREAT с повышенным speed_scale и дистанцией), HIDE: бежать
  к ближайшему кусту (группа "bush" — тот же источник, что у StealthComponent),
  войти -> скрыться. Механика: StealthComponent на врага + can_stealth=true в
  EnemyGruntProfile (сейчас false) — компонент уже универсален (Q7.14).
- ВЫХОД ИЗ УКРЫТИЯ (вердикт В3, 17.10.2026): «никаких таймеров (это зло в нашей
  игре)... сейчас он вылезает когда игрока нет рядом... Пусть охраняет манекен».
  → непрерывная проверка дистанции (НЕ таймер): игрок дальше flee_exit_distance
  (ручка; гистерезис > detection_range 8.0 против oscillation «вышел-снова
  спрятался») -> вышел из стелса -> НОВОЕ СОСТОЯНИЕ GUARD: идти к манекену
  (DummyMannequin, группа "dummy_enemy" — видимый ориентир, честно как кусты в
  B3), держать дистанцию guard_standoff (ручка, родословная: stop_distance 1.5)
  и охранять. Игрок снова виден и триггер самосохранения ещё взведён (hp низкое)
  -> FLEE/HIDE повторно; hp в норме (в будущем — регенерация: «в будущем будет
  регенерация запускаться») -> обычные решения/бой.
- Засада из стелса (выпрыгивание на подошедшего игрока) — НЕ реализуем (вердикт
  17.10.2026: «засады он тоже не делает (но идея очень хорошая, для будущего
  босса добавим)») — в бэклоге кандидатов.
- Обнаружение скрытого врага игроком (В2) — ОТЛОЖЕНО: стелс врага пока = тот же
  механизм флага, что у игрока (визуал/раскрытие — после вердикта В2; В1:
  «стелс только скрывает от обнаружения, урон проходит как обычно» — атаки
  игрока по площади куста ПРОХОДЯТ по скрытому врагу обычными правилами ядра).

## РЕВИЗИЯ B4+ (Q7.25, вердикт 7/10 от 17.10.2026): пост-патруль и испуг
- «иногда враг зависает и стоит после патрулирования. Он должен по умолчанию
  идти охранять манекен — патрулировать рядом (без хардкода)» → GUARD =
  дойти до поста (группа guard_group — данные) и ПАТРУЛИРОВАТЬ орбитой
  guard_patrol_radius; пост по умолчанию при потерянном игроке —
  guard_post_enabled (Дуэлянт: вкл); guard_standoff (стояние) удалён.
- «враг при получении урона из засады должен пугаться и убегать, если противник
  не обнаружен» → fear_on_ambush_damage: HealthComponent.damaged(amount,
  attacker_pos) (ядро и раньше передавало позицию — теперь не выбрасывается;
  направление удара = честный факт контакта) → при НЕВИДИМОМ атакующем FLEE от
  источника при любом hp; снятие — видимость или dist > flee_exit_distance
  (без таймеров); повторный урон — повторный испуг (событийность).
- Стенды: sim_ai_flee 26/26 (F3 патруль у поста, F7 испуг от невидимого при
  hp 95/100 + бегство ОТ источника, F8 видимый атакующий — без испуга);
  sim_ai_bush 43/43 (S10 пост по умолчанию после поиска).
- РЕВИЗИЯ 2 (Q7.26, наблюдение заказчика −1 балл): «вытолкнули из куста —
  стоит пассивно» → HIDE проверяет ФАКТ стелса каждый тик: утрата стелса
  (вытолкнули/раскрыли) → угроза видна и близко → снова FLEE (полуплоское
  правило: прочь от игрока, не обратно в куст), иначе → GUARD. Без таймеров.
  Стенд: sim_ai_flee F9 (30/30, естественный body_exited).
- Стенд: sim_ai_flee (сид): hp врага опускаем ниже порога -> RETREAT/FLEE ->
  входит в куст -> is_stealthed=true -> телепорт/увод игрока далеко -> вышел ->
  GUARD: дошёл до манекена, держит standoff; игрок близко + hp низкое -> снова
  FLEE. Без таймеров — только дистанционные проверки.

## 3. Что уже готово из Фазы A (не пересоздаём)
Сидированный RNG; движок паттернов (pattern_length=1); подписки на исходы
(attack_finished/cancelled/stun_started); счётчики приёмки; честное восприятие
(атака «по анимации», блок «мечом»); Memory копит доли атак/блоков/мобильности
игрока (материал для «уверенности в победе»); AIIntent+shell исполнят любой
move_state; панель журнала ИИ покажет новые состояния заказчику вживую.

## 4. Требования ко всем шагам
- Поведение каждого шага — за ручками профиля (данные), дефолты сохраняют
  предыдущее поведение до включения заказчиком.
- Детерминированные стенды с фиксированными сидами на каждое поведение.
- Полный регресс-набор зелёный (enemy 8/8, core 12/12, block 20/20, chase 7/7 и пр.).
- Feel-чек заказчика в живой игре после каждого шага (одна проблема за раз).

## 5. ОТКРЫТЫЕ ВОПРОСЫ заказчику (ОТВЕТЫ ПОЛУЧЕНЫ 17.10.2026 — статусы ниже)
1. Скрытый враг и игрок: становится ли он НЕЦЕЛЕУКАЗУЕМЫМ (атаки игрока не
   находят его, засада Ренгара на него не срабатывает)? Или стелс врага только
   визуальный (полупрозрачность)?
   → ОТВЕТ (17.10.2026): «Стелс только скрывает от обнаружения, урон проходит

   по кусту -> раскрывается? таймер?

   «убедился что потерял преследователя»?
